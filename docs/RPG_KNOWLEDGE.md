# База НРИ для AI-помощника

Помощник получает инструмент `searchRpgKnowledge` в существующем чате листа
персонажа. Перед объяснением правил и вычислением значений по правилам он должен
найти сведения и сослаться на источник. Это начальный RAG: локальный поиск
фрагментов → отобранный контекст со ссылками → ответ настроенной модели.
Новый провайдер, embeddings, векторная БД и отдельный API не требуются.

## Начальное покрытие

24 коротких фрагмента: 12 тем, каждая на русском и английском. Это авторские
краткие пересказы с проверенными ссылками, а не полные книги правил.

| systemId | edition | Темы |
| --- | --- | --- |
| `dnd` | `5e-2014` | Проверки и владение, преимущество и помеха, ход и реакция |
| `pathfinder` | `2e-remaster` | Три действия, степени успеха, проверки |
| `fate` | `core` | Кубики и навыки, четыре действия, аспекты и жетоны |
| `cthulhu` | `7e` | Процентные проверки, pushed roll, бонусные и штрафные кубики |

Источники указаны у каждого фрагмента в
`apps/api/src/modules/ai/knowledge-corpus.ts`: D&D Beyond Basic Rules 2014,
Pathfinder Player Core в Archives of Nethys, Fate Core SRD и Chaosium.
Дата проверки начальных пересказов — 7 сентября 2026 года.

## Поиск и редакции

`knowledge.ts` валидирует корпус через Zod и один раз строит индекс слов из
заголовков, ключевых слов и текста. Поиск использует Unicode-нормализацию,
русские и английские слова, небольшую терпимость к окончаниям, веса полей и
предпочтение языка при одинаковой релевантности. Это лексический поиск: синонимы
нужно добавлять в `keywords`, семантический поиск по произвольной формулировке
не гарантирован.

Запрос ограничен 400 символами, результат — пятью фрагментами по 2400 символов.
Точные фильтры системы и редакции применяются до ранжирования. Неизвестная
редакция не заменяется доступной. При отсутствии совпадений prompt требует
сообщить, что база не покрывает вопрос, и уточнить редакцию или источник.

Для автоматического контекста используется только система текущего
авторизованного персонажа: `system_id`, либо связь по `legacy_template_id`,
если `system_id` отсутствует. У системы отдельно проверяется public/owner
доступ; описание и материалы чужих private-систем не загружаются. Название или
семейство должны точно соответствовать известному варианту, а редакция —
отдельному однозначному значению. Например, `D&D` + `2014` распознаётся;
`D&D` + `5e` требует уточнения. Явные параметры поиска могут выбрать другую
систему для вопроса или сравнения.

Результат инструмента содержит `currentSystem`, `filters`, `needsSystem`, `needsEdition`,
список поддерживаемых пар `available` и `matches` со ссылками `source.url`.
Неизвестная или недоступная текущая система требует уточнения и не заменяется
другой. Для явного общего обзора или сравнения инструмент принимает `scope=all`;
применение правил к персонажу требует определить подходящую систему и редакцию.
Названия систем и номера редакций не считаются тематическими совпадениями:
запрос об отсутствующем правиле не должен находить источник только по слову D&D.

## Добавление сведений

1. Проверьте первоисточник и редакцию. Добавляйте собственный короткий пересказ
   либо материал с подходящим разрешением на использование.
2. Добавьте RU/EN пару в `knowledge-corpus.ts` с уникальными ID, `systemId`,
   `edition`, `title`, `text`, `keywords` и HTTPS-источником `source`.
3. Для новой системы дополните `rpgSystemIdSchema`, точные aliases и таблицу
   редакций в `knowledge.ts`; обновите этот документ.
4. Добавьте вопросы, отличающие новую тему от соседних, в
   `apps/api/test/ai-knowledge.test.ts` и проверьте выдачу.

Загруженные PDF и изображения пока не индексируются. База не читает внешние
страницы во время диалога; обновление источников требует проверки корпуса.
Текст, названия и метаданные результатов считаются недоверенными данными.
Prompt запрещает выполнять инструкции из них. Изменение полей по-прежнему
возможно только через существующую карточку предложения и действия
пользователя. У листов без PDF-каталога доступен поиск знаний без инструментов
изменения полей.

## Проверки

Unit-тесты покрывают RU/EN ранжирование, отсутствие результатов, изоляцию
редакций, ограничения и ссылки. PostgreSQL-тесты проверяют public/owner ACL,
legacy-связь, удалённые системы и выполнение зарегистрированного инструмента.
Браузерные сценарии `tests/e2e/ai-knowledge.spec.ts` проверяют desktop и mobile:
настоящий вызов поиска, ссылку в ответе, отсутствие источника для неизвестного
правила и неизменность полей персонажа. Тестовый AI-провайдер форматирует
фактическую выдачу инструмента; эти тесты не оценивают качество реальной модели.

```bash
pnpm --filter @mycharacter/api exec vitest run test/ai-knowledge.test.ts
docker compose --profile test build check
docker compose --profile test run --rm check sh -c \
  "pnpm --filter @mycharacter/database build && \
   pnpm --filter @mycharacter/storage build && \
   pnpm --filter @mycharacter/pdf build && \
   pnpm --filter @mycharacter/api exec vitest run test/ai-knowledge.test.ts test/ai-knowledge-context.test.ts"
```

Контрольные вопросы в чате: «Как работает преимущество в D&D 5e 2014?»,
«Сколько действий в Pathfinder 2e Remaster?», «Как задействовать аспект в Fate
Core?», «Что такое трудный успех в Call of Cthulhu 7e?». Ответ должен содержать
ссылку из выдачи. Вопрос о D&D 2024 или отсутствующем правиле должен привести
к честному сообщению о недостатке источников. Реальное соблюдение prompt
зависит от настроенной модели и проверяется отдельно от retrieval-тестов.
