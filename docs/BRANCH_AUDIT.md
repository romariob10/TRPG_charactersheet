## Как объединены истории

Подтверждены точные равенства деревьев:

```text
dev = 71dba64 = 5965efc
tree: b2e79996d26555bc4020cb0849e68d67b1c77351

00cd36a = 8f30573
tree: ff8fad2aabb13d32b09b5d65343c301a3f1ac65b

00cd36a parents: 71dba64, 8f30573
```

Снимок `5965efc` продолжается до `6553c80`. Между `6553c80` и `f90358e` меняется
только поле `version` с `0.0.11` на `0.1.0` в девяти `package.json`; остальные
поля и файлы идентичны. `f90358e` входит в историю `8f30573`.

Трёхстороннее объединение с явной подтверждённой базой:

```bash
git merge-tree --write-tree --merge-base=5965efc dev 8f30573
```

дало дерево `8f30573` без конфликтов: локальная сторона полностью совпадает с
базой. Коммит `00cd36a` создан на подветке от `dev` с обоими родителями.
`git diff --quiet 00cd36a 8f30573` подтвердил отсутствие изменений содержимого.
Существующие коммиты, ветки и пользовательские данные не удалялись и не
переписывались; новых релизных версий не вводилось. Перенос в `dev`, `main` или
remote не выполнялся.

## Исправления CI/CD и проверок

Проблемы ниже обнаружены в исходном `8f30573` и исправлены на
`codex/fix-branch-audit`. Таблица описывает реализованное поведение; фактически
завершённые проверки и ещё выполняющиеся прогоны перечислены отдельно.

| Исходная проблема | Последствие | Реализованное исправление |
| --- | --- | --- |
| Production deploy стартовал параллельно CI. | В production мог попасть коммит с неуспешными проверками. | Автозапуск следует за успешным CI push-run для `main` этого репозитория. Job `verify` проверяет текущий SHA `main` и последний CI-run именно для него; старый успешный run не заменяет новый незавершённый или неуспешный. |
| Ручной deploy допускал другую ветку. | Код другой ветки мог публиковаться под тегом `main`. | Ручной запуск проходит только с `refs/heads/main` и той же проверкой успешного CI для текущего SHA. |
| Deploy использовал изменяемый тег `main` и текущий checkout. | Образы, проверенный код и конфигурация могли относиться к разным коммитам. | Сборка получает проверенный полный SHA; запуск использует `sha-<полный SHA>` для web/API/worker/migrate и detached checkout того же коммита. Перед переключением checkout и после загрузки образов повторно проверяется, что `main` не продвинулся. |
| Production sync принудительно заменял checkout. | Локальные изменения могли быть потеряны. | Deploy останавливается при изменённых или неотслеживаемых файлах; принудительная перезапись checkout удалена. |
| У `migrate` была только локальная сборка. | При обновлении приложений могли запускаться старые миграции. | `migrate` использует API production-образ того же SHA и явно загружается перед запуском; `up --no-build` исключает случайную локальную пересборку. |
| CI собирал только внутренние runtime-пакеты. | Production-сборка приложений оставалась непроверенной. | После lint/typecheck CI выполняет `pnpm build`; задания имеют явные лимиты времени. |
| E2E proxy использовал общий сервис `web`. | Серверные запросы web могли идти в обычный API. | Добавлен `web-e2e` с `INTERNAL_API_URL=http://api-e2e:4000` и отдельным Next.js-кэшем; Caddy и зависимости E2E направлены на него. |
| E2E worker объявлял готовность до регистрации обработчиков. | Тесты могли начать работу до готовности фоновых заданий. | Worker создаёт readiness-файл после регистрации обработчиков, удаляет его при старте и штатной остановке; Compose healthcheck использует этот файл в development, E2E и production. |
| Холодный запуск E2E мог исчерпать healthcheck retries во время сборки. | Исправный стек преждевременно считался неготовым. | Для `api-e2e`, `worker-e2e` и `web-e2e` задан `start_period: 90s`; проверки готовности сохранены. |
| Тест конкурентной смены пароля имел отдельный таймаут 1 секунду. | Реальные Argon2-операции под нагрузкой вызывали ложное падение. | Удалён только локальный `1_000` override; действует стандартный Vitest timeout 5 секунд. Барьеры, утверждения теста и код авторизации не изменены. |

## Worktree и безопасные следующие шаги

`git worktree list --porcelain` показал две записи `prunable` с причиной
`gitdir file points to non-existent location`:

- `/private/tmp/trpg-latest-sheets.6h2sWc` — `codex/dev-latest-sheets-fixes`;
- `/private/tmp/trpg-sheet-sync.zbfadk` — `codex/prod-sheet-sync-and-contrast`.

Каталоги отсутствуют; ветки и коммиты доступны. Пометка `gone` для upstream второй
ветки относится к локальному cached ref и не подтверждает текущее состояние сервера.
Обе доказанно устаревшие записи метаданных очищены. Повторный
`git worktree list --porcelain` показывает только основной checkout. Ветки и их
коммиты сохранены; ссылки `main` и `dev` остались на исходных SHA.

   разрешением на удаление. Для будущих устаревших worktree сначала просматривать
   `git worktree prune --dry-run` и проверять, что каталоги действительно отсутствуют.
5. Вести новые задачи от проверенного `dev` и переносить законченные изменения,
   сохраняя существующую историю.
